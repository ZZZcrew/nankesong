# FamLink 代际沟通AI助手 - 后端技术方案（黑客松版）

> 版本: V1.0 Hackathon  
> 时间预算: 24小时  
> 核心焦点: Agent情感翻译引擎

---

## 1. 项目定位

### 1.1 核心目标
24小时内构建可演示的MVP，聚焦 **Agent三大场景**：
1. **生成日记**: 原始数据 → 辈友好型日记
2. **回复长辈**: 基于日记回答长辈提问
3. **传达留言**: 长辈关怀留言 → 通知小辈

### 1.2 简化原则
| 原复杂设计 | 黑客松简化方案 |
|-----------|--------------|
| PostgreSQL关系库 | SQLite单文件数据库 |
| Milvus向量记忆 | 无（直接用LLM上下文） |
| JWT鉴权体系 | 无（user_id直接传参） |
| Celery异步队列 | 同步调用（前端Loading动画掩饰） |
| 多数据源适配 | Mock数据生成脚本 |

## 4. 数据存储设计（SQLite极简版）

### 4.2 配置文件设计

**应用配置类（Settings）**：
- 使用pydantic-settings管理配置，支持.env文件读取
- 必填配置项：`OPENAI_API_KEY`（OpenAI API密钥）
- 可选配置项:`BASE_URL`
- 可选配置项：`MODEL_NAME`（默认：gpt-4o）

**FastAPI入口设计（main.py）**：
- 应用标题：FamLink API
- 应用描述：代际沟通AI助手 - 黑客松版
- 版本号：1.0.0
- 启动钩子：自动创建数据库表（调用Base.metadata.create_all）
- 路由注册：包含数据管理路由和Agent引擎路由

### 4.3 三张核心表设计

#### 表1：raw_data（原始数据表）

**用途**：存储小辈的日常碎片数据（图文/视频）

| 字段 | 类型 | 说明 | 约束 |
|------|------|------|------|
| id | INTEGER | 主键 | 自增 |
| item_id | TEXT | 数据唯一标识 | UNIQUE NOT NULL |
| type | TEXT | 数据类型 | NOT NULL（枚举值：image/video/text） |
| content | TEXT | 数据内容 | NOT NULL（URL或文本内容） |
| description | TEXT | 原始配文 | 可空 |
| status | TEXT | 数据状态 | DEFAULT 'pending'（枚举值：pending/deleted/processed） |
| created_at | TIMESTAMP | 创建时间 | DEFAULT CURRENT_TIMESTAMP |

**状态流转**：
- `pending`：待审核（初始状态）
- `deleted`：已删除（小辈筛选后标记）
- `processed`：已处理（生成日记后标记）

#### 表2：diaries（日记表）

**用途**：存储Agent生成的长辈友好型家书

| 字段 | 类型 | 说明 | 约束 |
|------|------|------|------|
| id | INTEGER | 主键 | 自增 |
| summary_id | TEXT | 日记唯一标识 | UNIQUE NOT NULL（格式：sum_xxx） |
| date | DATE | 日记日期 | NOT NULL |
| title | TEXT | 日记标题 | NOT NULL（15字内） |
| content | TEXT | 日记正文 | NOT NULL（100-150字） |
| cover_image | TEXT | 插图图片列表 | JSON数组格式（注意：单数形式） |
| suggested_questions | TEXT | 建议问题列表 | JSON数组格式（2-3个问题） |
| raw_data_ids | TEXT | 关联原始数据ID | JSON数组格式 |
| created_at | TIMESTAMP | 创建时间 | DEFAULT CURRENT_TIMESTAMP |

**关键设计**：
- `summary_id`字段名严格遵循接口文档定义
- `cover_image`字段名使用单数形式（接口文档要求）
- JSON字段存储数组，需在读取时解析

#### 表3：messages（留言表）

**用途**：存储长辈→小辈的关怀留言通知

| 字段 | 类型 | 说明 | 约束 |
|------|------|------|------|
| id | INTEGER | 主键 | 自增 |
| summary_id | TEXT | 关联日记ID | NOT NULL |
| elder_query | TEXT | 长辈原始留言 | NOT NULL |
| agent_reply | TEXT | Agent回复 | 可空 |
| transfer_content | TEXT | 传达给小辈的内容 | 可空（20-30字简洁通知） |
| is_transferred | BOOLEAN | 是否已查看 | DEFAULT FALSE |
| created_at | TIMESTAMP | 创建时间 | DEFAULT CURRENT_TIMESTAMP |

**业务逻辑**：
- 当Agent判断action=notify_younger时触发存储
- 小辈通过GET /messages接口获取未读留言
- 查看后is_transferred标记为true

### 4.4 数据模型类设计

**ORM框架**：SQLAlchemy 2.0 + declarative_base

**三个核心类**：

| 类名 | 对应表 | 核心字段 | 特殊处理 |
|------|--------|----------|----------|
| RawData | raw_data | item_id, type, content, description, status | status字段用于状态流转 |
| Diary | diaries | summary_id, title, content, cover_image | JSON字段需dumps/loads处理 |
| Message | messages | summary_id, elder_query, transfer_content | is_transferred用于未读标记 |

**数据库连接**：
- 连接字符串：`sqlite:///data/famlink.db`
- Session工厂：sessionmaker(bind=engine)
- 自动建表：Base.metadata.create_all(engine)

**导入依赖**：
- datetime：用于created_at默认值
- Boolean：用于is_transferred字段
- Text/TIMESTAMP/String：对应各字段类型

### 4.2 三张核心表

```sql
-- 1. 原始数据表（小辈的日常碎片）
CREATE TABLE raw_data (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    item_id TEXT UNIQUE NOT NULL,
    type TEXT NOT NULL,              -- 'image', 'video', 'text'
    content TEXT NOT NULL,           -- URL或文本内容
    description TEXT,                -- 原始配文
    status TEXT DEFAULT 'pending',   -- 'pending'(待审核), 'deleted'(已删除), 'processed'(已处理)
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- 2. 日记表（Agent生成的家书，严格遵循接口文档字段名）
CREATE TABLE diaries (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    summary_id TEXT UNIQUE NOT NULL,  -- 接口文档定义的summary_id（格式: sum_xxx）
    date DATE NOT NULL,
    title TEXT NOT NULL,
    content TEXT NOT NULL,            -- 长辈友好型日记内容
    cover_image TEXT,                 -- JSON数组: ["url1", "url2"]（注意：单数形式）
    suggested_questions TEXT,         -- JSON数组: ["问题1", "问题2"]
    raw_data_ids TEXT,                -- 关联的原始数据ID列表
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- 3. 留言表（长辈→小辈的关怀留言，严格遵循接口文档字段名）
CREATE TABLE messages (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    summary_id TEXT NOT NULL,        -- 接口文档定义的summary_id
    elder_query TEXT NOT NULL,       -- 长辈的问题/留言（接口文档的query字段）
    agent_reply TEXT,                -- Agent的回复（接口文档的reply_text字段）
    transfer_content TEXT,           -- 传达给小辈的内容
    is_transferred BOOLEAN DEFAULT FALSE,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

### 4.2 数据模型（Python）

```python
# app/models/database.py
from sqlalchemy import create_engine
from sqlalchemy.orm import sessionmaker

engine = create_engine("sqlite:///data/famlink.db")
Session = sessionmaker(bind=engine)

from sqlalchemy import Column, Integer, String, Text, TIMESTAMP, Boolean
from sqlalchemy.ext.declarative import declarative_base
from datetime import datetime

Base = declarative_base()

class RawData(Base):
    __tablename__ = "raw_data"
    
    id = Column(Integer, primary_key=True)
    item_id = Column(String(50), unique=True, nullable=False)
    type = Column(String(20), nullable=False)
    content = Column(Text, nullable=False)
    description = Column(Text)
    status = Column(String(20), default="pending")
    created_at = Column(TIMESTAMP, default=datetime.now)

class Diary(Base):
    __tablename__ = "diaries"
    
    id = Column(Integer, primary_key=True)
    summary_id = Column(String(50), unique=True)  # 接口文档定义的summary_id
    date = Column(String(10), nullable=False)
    title = Column(String(200), nullable=False)
    content = Column(Text, nullable=False)
    cover_image = Column(Text)  # JSON string（注意：单数形式）
    suggested_questions = Column(Text)  # JSON string
    raw_data_ids = Column(Text)  # JSON string
    created_at = Column(TIMESTAMP, default=datetime.now)

class Message(Base):
    __tablename__ = "messages"
    
    id = Column(Integer, primary_key=True)
    summary_id = Column(String(50), nullable=False)  # 接口文档定义的summary_id
    elder_query = Column(Text, nullable=False)
    agent_reply = Column(Text)
    transfer_content = Column(Text)
    is_transferred = Column(Boolean, default=False)  # Boolean已导入
    created_at = Column(TIMESTAMP, default=datetime.now)  # datetime已导入
```

### 5.2 Agent核心服务类设计

**类名**：FamLinkAgent

**职责**：统一调度三大场景的LLM处理逻辑

**初始化参数**：
- client：OpenAI客户端实例（需传入OPENAI_API_KEY）
- model：模型名称（固定为gpt-4o）

**三大核心方法**：

#### 方法1：generate_diary（场景1：日记生成）

**输入参数**：
- raw_items：原始数据列表（包含type/content/description字段）
- date：目标日期（YYYY-MM-DD格式）

**处理流程**：
1. 数据预处理：调用`_preprocess_raw_data()`进行脱敏和语义转化
2. Prompt构建：调用`_format_items()`格式化数据并填充DIARY_PROMPT模板
3. LLM调用：向OpenAI发送请求，temperature=0.7，response_format=json_object
4. 结果解析：从LLM响应中提取title/content/suggested_questions
5. 补充封面：从raw_items中筛选image/video类型的content字段，取前3个作为cover_image

**输出结构**：
```
{
    "title": "小明今天吃了一顿丰盛的晚餐",
    "content": "爸妈，我今天工作挺努力的...",
    "cover_image": ["url1", "url2"],  // 注意：单数形式
    "suggested_questions": ["这是和谁一起吃的？"]
}
```
注意：summary_id由API层生成，不在Agent层处理

#### 方法2：chat_with_elder（场景2：长辈对话）

**输入参数**：
- diary_content：日记正文内容
- diary_title：日记标题
- elder_query：长辈的提问或留言

**处理流程**：
1. Prompt构建：填充CHAT_PROMPT模板，传入日记上下文和长辈问题
2. LLM调用：temperature=0.8（稍高以增加亲和力），response_format=json_object
3. 结果解析：提取reply_text和action字段

**输出结构**：
```
{
    "reply_text": "奶奶您好！小明是和同事一起...",
    "action": "reply" 或 "notify_younger"  // 关键判断字段
}
```

**action判断逻辑**：
- `reply`：一般性询问，Agent直接回答即可
- `notify_younger`：长辈表达担忧/想念/关心情绪，需通知小辈

#### 方法3：transfer_message（场景3：留言传达）

**输入参数**：
- summary_id：关联的日记ID
- elder_query：长辈的原始留言
- agent_reply：Agent之前的回复

**处理流程**：
1. Prompt构建：填充TRANSFER_PROMPT模板，传入长辈留言和Agent回复
2. LLM调用：temperature=0.7，response_format=json_object
3. 结果解析：提取transfer_content/emotion_type/suggested_reply

**输出结构**：
```
{
    "transfer_content": "奶奶想你了，问你吃饭没",  // 20-30字简洁通知
    "emotion_type": "想念",
    "suggested_reply": "刚吃过啦，周末去看您",  // 建议小辈回复
    "summary_id": "sum_998"
}
```

**设计要点**：
- transfer_content控制在20-30字，保留情感温度但简洁明了
- suggested_reply为可选字段，给小辈提供回应建议

#### 内部辅助方法设计

**方法4：_preprocess_raw_data（数据预处理）**

**职责**：脱敏 + 网络流行语转化

**处理规则**：
1. 字段选择：
   - text类型：处理content字段（主要内容）
   - image/video类型：处理description字段（配文）

2. 网络流行语转化映射表：
   | 原词 | 转化结果 |
   |------|----------|
   | emo | 心情有点低落 |
   | 躺平 | 休息放松 |
   | PUA | 工作遇到挑战 |
   | 绝绝子 | 很棒 |
   | 社畜 | 工作努力 |
   | 摸鱼 | 休息放松 |
   | 摔成狗了 | 有点小意外 |

3. 敏感词移除列表：工资、领导、老板、薪资、公司

**输出字段**：
- type：保留原类型
- content：保留原URL
- description：处理后的配文（image/video类型）
- processed_text：统一存储处理后的文本（用于Prompt填充）

**方法5：_format_items（数据格式化）**

**职责**：将预处理后的数据格式化为Prompt中的列表文本

**格式规则**：
- text类型：`文字动态: {processed_text}`
- image类型：`图片配文: {processed_text}`
- video类型：`视频配文: {processed_text}`

**输出**：换行分隔的字符串，直接填充到Prompt模板的{items}位置

## 6. Prompt模板设计（核心）

### 6.1 场景1：日记生成Prompt（DIARY_PROMPT）

**模板结构**：

**1. 系统角色定义**
- 角色：FamLink家庭情感翻译官
- 职责：帮助年轻人向长辈传递生活动态

**2. 任务描述**
将年轻人的日常碎片信息转化为长辈能理解、愿意看、感到温暖的"日记"

**3. 代际语义转化规则库**

**负面情绪转化表**：
| 年轻人表达 | 长辈友好表达 |
|-----------|-------------|
| 上班真累，被PUA了 | 今天工作很努力，遇到一些挑战但都解决了 |

### 6.4 Prompt工程核心策略总结

**策略1：代际语义转化**
- 负面情绪 → 积极表达（保持真实但不引发担忧）
- 网络流行语 → 长辈理解语言（消除理解障碍）
- 敏感信息 → 过滤移除（保护隐私）

**策略2：长辈对话判断**
- 直接回答：温和耐心，不过度暴露细节
- 触发通知：情绪识别（检测担心/想念关键词）→ notify_younger

**策略3：留言传达策略**
- 提炼核心关怀点（20-30字）
- 保留情感温度（不冷漠）
- 建议小辈回应方式（促进互动）

**策略4：JSON格式强制**
- 所有场景使用response_format={"type": "json_object"}
- 避免格式解析失败
- 便于程序化处理

### 7.2 接口1：获取当日原始数据

**接口路径**：`GET /api/v1/data/raw`

**功能描述**：根据日期获取未经处理的原始图文/视频数据，供小辈控制台展示待筛选列表

**请求参数**（Query参数）：
| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| date | String | 是 | 目标日期，格式YYYY-MM-DD |
| user_id | String | 否 | 当前小辈用户的ID（模拟鉴权） |

**处理流程**：
1. 获取数据库Session实例
2. 解析date参数为datetime对象（格式：YYYY-MM-DD）
3. 计算时间范围：当天00:00:00 ~ 当天23:59:59
4. 查询raw_data表，条件：status='pending' 且 created_at在目标日期范围内
5. 遍历查询结果，提取字段：item_id、type、content、description、timestamp（created_at转unix时间戳）

**响应结构**：
```
{
  "code": 200,
  "message": "success",
  "data": {
    "date": "2023-11-24",
    "items": [
      {
        "item_id": "raw_001",
        "type": "image",
        "content": "https://example.com/images/hotpot.jpg",
        "description": "今天被 leader 骂了，怒吃一顿火锅",
        "timestamp": "1695552000"
      }
    ]
  }
}
```

**数据字段说明**：
- `item_id`：原始数据唯一标识
- `type`：数据类型枚举（image/video/text）
- `content`：图片/视频URL，或纯文本内容
- `description`：原始配文/描述
- `timestamp`：Unix时间戳（秒级）

### 7.3 接口2：批量删除原始数据

**接口路径**：`POST /api/v1/data/raw/delete`

**功能描述**：批量删除不需要交给Agent处理的原始数据（小辈筛选敏感/无关内容）

**请求参数**（Body参数，JSON格式）：
| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| item_ids | Array[String] | 是 | 需要删除的原始数据ID列表 |
| user_id | String | 是 | 当前小辈用户ID（模拟鉴权） |

**请求示例**：
```
{
  "item_ids": ["raw_001", "raw_003"],
  "user_id": "user_123"
}
```

**处理流程**：
1. 获取数据库Session实例
2. 遍历item_ids列表
3. 对每个item_id，查询raw_data表（条件：item_id匹配）
4. 若存在，更新status字段为'deleted'（软删除，不物理删除）
5. 统计deleted_count
6. 提交事务（db.commit()）

**响应结构**：
```
{
  "code": 200,
  "message": "成功删除 2 条数据",
  "data": {
    "deleted_count": 2
  }
}
```

**业务逻辑**：
- 软删除策略：仅修改status字段，保留数据用于后续审计
- 已删除的数据不会出现在接口1的查询结果中
- 不存在的item_id会被忽略，不计入deleted_count

### 7.4 接口3：生成日记（Agent核心接口）

**接口路径**：`POST /api/v1/agent/generate-summary`

**功能描述**：触发Agent对当日数据进行"长辈友好型"翻译，生成家书结果

**请求参数**（Body参数，JSON格式）：
| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| date | String | 是 | 目标日期，格式YYYY-MM-DD |
| user_id | String | 是 | 当前小辈用户ID（模拟鉴权） |

**请求示例**：
```
{
  "date": "2023-11-24",
  "user_id": "user_123"
}
```

**处理流程**：
1. 获取数据库Session实例
2. 解析date参数为datetime对象，计算时间范围
3. 查询raw_data表，条件：status='pending' 且 created_at在目标日期范围内
4. 将查询结果转换为raw_data_list（提取type/content/description字段）
5. 调用Agent服务的generate_diary方法，传入raw_data_list和date
6. Agent返回：title、content、cover_image、suggested_questions
7. 生成summary_id（格式：sum_xxx，xxx为当前时间戳%10000）
8. 创建Diary实例，存储到diaries表：

   - raw_data_ids：关联的原始数据ID列表（JSON数组）
9. 更新raw_data表中对应记录的status为'processed'
10. 提交事务（db.commit()）
11. 返回响应（注意：cover_image字段为单数形式）

**响应结构**：
```
{
  "code": 200,
  "message": "Agent 处理完成",
  "data": {
    "summary_id": "sum_998",
    "title": "小明今天吃了一顿丰盛的晚餐",
    "content": "爸妈，我今天工作挺努力的...",
    "cover_image": ["https://example.com/images/hotpot.jpg"],

      "看着真香，这是和谁一起吃的呀？",
      "最近降温了，吃饭穿够衣服没？"
    ]
  }
}
```

**关键注意事项**：
- `cover_image`字段使用单数形式（接口文档要求）
- `summary_id`格式固定为sum_xxx
- 已处理的数据status变为'processed'，不会再次出现在接口1中
- Agent调用耗时较长（2-5秒），前端需显示"Agent思考中..."动画

### 7.5 接口4：长辈对话（Agent核心接口）

**接口路径**：`POST /api/v1/agent/chat`

**功能描述**：接收长辈的提问，结合当前日记上下文，返回Agent的贴心回答或触发关怀通知

**请求参数**（Body参数，JSON格式）：
| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| query | String | 是 | 长辈的问题或留言 |
| summary_id | String | 是 | 当前日记的ID，让Agent知道长辈在看哪篇日记 |

**请求示例**：
```
{
  "query": "看着真香，这是和谁一起吃的呀？",
  "summary_id": "sum_998"
}
```

**处理流程**：
1. 获取数据库Session实例
2. 查询diaries表，条件：summary_id匹配请求参数中的summary_id
3. 提取diary记录的content和title字段
4. 调用Agent服务的chat_with_elder方法，传入：
   - diary_content：日记正文
   - diary_title：日记标题
   - elder_query：长辈的问题
5. Agent返回：reply_text、action、emotion_type
6. **分支判断**：
   
   **分支A：action='reply'**（直接回答）
   - 直接返回响应，无需额外处理

     - summary_id：日记ID
     - elder_query：长辈原始留言
     - agent_reply：Agent的回复
     - transfer_content：传达给小辈的内容
     - is_transferred：FALSE（未读标记）
   - 提交事务（db.commit()）
   - 返回响应时包含transfer_content字段

**响应结构（分支A：直接回答）**：
```
{
  "code": 200,
  "message": "success",
  "data": {
    "reply_text": "奶奶您好！我看照片里小明是和同事一起聚餐呢...",
    "action": "reply"
  }
}
```

**响应结构（分支B：触发通知）**：
```
{
  "code": 200,
  "message": "success",
  "data": {
    "reply_text": "奶奶，小明看到您的留言会很开心的。我会帮您转告他。",
    "action": "notify_younger",
    "transfer_content": "奶奶想你了，问你吃饭没"
  }
}
```

**业务逻辑**：
- `action`字段是关键判断依据，枚举值：reply/notify_younger
- `notify_younger`场景下，transfer_content字段会返回给前端供显示
- Message表的is_transferred字段用于标记未读状态

```python
from fastapi import APIRouter, Query
from sqlalchemy.orm import Session
from app.models.database import Session as get_db
from app.models.raw_data import RawData
from pydantic import BaseModel

router = APIRouter()

# ========== 接口1: GET /api/v1/data/raw ==========

@router.get("/raw")
async def get_raw_data(
    date: str = Query(..., description="目标日期，格式为 YYYY-MM-DD"),
    user_id: str = Query(None, description="当前小辈用户的 ID")
):
    """

    接口路径: GET /api/v1/data/raw

    - date (必填): YYYY-MM-DD
    - user_id (选填): 用户ID

    from datetime import datetime
    target_date = datetime.strptime(date, "%Y-%m-%d")
    next_date = target_date.replace(hour=23, minute=59, second=59)
    
    items = db.query(RawData).filter(
        RawData.status == "pending",
        RawData.created_at >= target_date,
        RawData.created_at <= next_date
    ).all()
    
    return {
        "code": 200,
        "message": "success",
        "data": {
            "date": date,
            "items": [
                {
                    "item_id": item.item_id,
                    "type": item.type,  # image, video, text
                    "content": item.content,
                    "description": item.description,
                    "timestamp": str(int(item.created_at.timestamp()))
                }
                for item in items
            ]
        }
    }

# ========== 接口2: POST /api/v1/data/raw/delete ==========

class DeleteRequest(BaseModel):

    user_id: str

@router.post("/raw/delete")
async def delete_raw_data(request: DeleteRequest):
    """
    批量删除原始数据
    
    接口路径: POST /api/v1/data/raw/delete
    Body参数:
    - item_ids: ["raw_001", "raw_003"]
    - user_id: "user_123"
    
    响应格式: 严格遵循接口文档
    """
    db = get_db()
    deleted_count = 0
    
    for item_id in request.item_ids:
        item = db.query(RawData).filter(
            RawData.item_id == item_id
        ).first()
        if item:
            item.status = "deleted"
            deleted_count += 1
    
    db.commit()
    
    return {
        "code": 200,
        "message": f"成功删除 {deleted_count} 条数据",
        "data": {
            "deleted_count": deleted_count
        }
    }
```

```python
        RawData.status == "pending",
        RawData.created_at >= target_date,
        RawData.created_at <= next_date
    ).all()
    
    # Step 2: 调用Agent生成日记
    raw_data_list = [
        {
            "type": item.type,
            "content": item.content,
            "description": item.description
        }
        for item in raw_items
    ]
    
    diary_result = agent.generate_diary(raw_data_list, request.date)
    
    # Step 3: 生成summary_id (格式: sum_xxx)
    summary_id = f"sum_{int(time.time()) % 10000}"
    
    # Step 4: 存储到数据库
    diary = Diary(
        summary_id=summary_id,
        date=request.date,
        title=diary_result["title"],
        content=diary_result["content"],
        cover_image=json.dumps(diary_result.get("cover_image", [])),
        suggested_questions=json.dumps(diary_result.get("suggested_questions", [])),
        raw_data_ids=json.dumps([item.item_id for item in raw_items])
    )
    db.add(diary)
    
    # 更新原始数据状态
    for item in raw_items:
        item.status = "processed"
    
    db.commit()
    
    # 返回格式严格遵循接口文档
    return {
        "code": 200,
        "message": "Agent 处理完成",
        "data": {
            "summary_id": summary_id,
            "title": diary_result["title"],
            "content": diary_result["content"],
            "cover_image": diary_result.get("cover_image", []),  # 注意：单数形式
            "suggested_questions": diary_result.get("suggested_questions", [])
        }
    }

class ChatRequest(BaseModel):
    query: str  # 长辈的问题
    summary_id: str  # 传递当前的上下文 ID

@router.post("/chat")
async def agent_chat(request: ChatRequest):
    """
    长辈对话（场景2 + 场景3）
    
    接口路径: POST /api/v1/agent/chat
    Body参数:
    - query: "看着真香，这是和谁一起吃的呀？"
    - summary_id: "sum_998"
    
    响应格式: 严格遵循接口文档
    - reply_text: Agent回复内容
    - action: "reply" / "notify_younger"
    """
    # Step 1: 加载日记
    db = get_db()
    diary = db.query(Diary).filter(
        Diary.summary_id == request.summary_id
    ).first()
    
    # Step 2: 调用Agent对话
    chat_result = agent.chat_with_elder(
        diary_content=diary.content,
        diary_title=diary.title,
        elder_query=request.query
    )
    
    # Step 3: 如果触发通知 → 调用留言传达
    if chat_result["action"] == "notify_younger":
        transfer_result = agent.transfer_message(
            summary_id=request.summary_id,
            elder_query=request.query,
            agent_reply=chat_result["reply_text"]
        )
        
        # 存储留言
        message = Message(
            summary_id=request.summary_id,
            elder_query=request.query,
            agent_reply=chat_result["reply_text"],
            transfer_content=transfer_result["transfer_content"],
            is_transferred=False
        )
        db.add(message)
        db.commit()
        
        # notify_younger场景需要返回transfer_content供前端显示
        return {
            "code": 200,
            "message": "success",
            "data": {
                "reply_text": chat_result["reply_text"],
                "action": "notify_younger",
                "transfer_content": transfer_result["transfer_content"]  # 补充返回
            }
        }
    
    # 普通回复
    return {
        "code": 200,
        "message": "success",
        "data": {
            "reply_text": chat_result["reply_text"],
            "action": chat_result["action"]  # reply / notify_younger
        }
    }
```

## 11. 关键技术要点总结

### 11.1 Agent三大场景核心逻辑

| 场景 | 输入 | 输出 | 关键Prompt技巧 |
|------|------|------|----------------|
| **生成日记** | 原始图文数据 | 日记标题+正文+建议问题 | 代际语义转化规则库 |
| **回复长辈** | 日记上下文+长辈提问 | Agent回复+action判断 | 长辈视角+情绪识别 |
| **传达留言** | 长辈留言+Agent回复 | 简洁通知内容 | 关怀提炼+建议回复 |

### 11.2 Prompt工程核心策略

1. **代际语义转化**
   - 负面情绪 → 积极表达
   - 网络流行语 → 长辈理解语言
   - 敏感信息 → 过滤移除

2. **长辈对话策略**
   - 直接回答: 温和耐心，不过度暴露细节
   - 触发通知: 情绪识别（担心/想念）→ notify_younger

3. **留言传达策略**
   - 提炼核心关怀点（20-30字）
   - 保留情感温度
   - 建议小辈回应方式

### 11.3 前端配合技巧

- **LLM调用耗时**: 前端加"Agent思考中..."Lottie动画（2-3秒）
- **长辈提问**: 提供预设问题按钮（降低输入门槛）
- **留言通知**: 小辈控制台弹出提示卡片
