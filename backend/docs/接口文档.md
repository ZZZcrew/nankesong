
### 全局说明
* **基础路径 (Base URL):** `/api/v1`
* **请求头 (Headers):** 需携带 `Content-Type: application/json`，将 `user_id` 直接放在请求体中模拟
* **通用返回格式:**
  ```json
  {
    "code": 200,          // 业务状态码，200表示成功
    "message": "success", // 状态描述
    "data": {}            // 核心数据负载
  }
  ```

---

### 1. 获取当日原始数据 API (前端待初筛列表)
前端小辈控制台调用此接口，获取系统（Mock 或真实抓取）暂存的当日生活碎片。

* **接口路径:** `GET /api/v1/data/raw`
* **功能描述:** 根据日期获取未经处理的原始图文/视频数据。
* **Query 参数:**
  * `date` (String, 必填): 目标日期，格式为 `YYYY-MM-DD`。
  * `user_id` (String, 选填): 当前小辈用户的 ID。
* **响应示例 (Response):**
  ```json
  {
    "code": 200,
    "message": "success",
    "data": {
      "date": "2023-11-24",
      "items": [
        {
          "item_id": "raw_001",
          "type": "image",       // 类型：image, video, text
          "content": "https://example.com/images/hotpot.jpg", // 图片或视频的URL，若是纯文本则为文本内容
          "description": "今天被 leader 骂了，怒吃一顿火锅", // 原始描述/配文
          "timestamp": "1695552000"
        },
        {
          "item_id": "raw_002",
          "type": "text",
          "content": "摔成狗了",
          "description": "",
          "timestamp": "1695556000"
        }
      ]
    }
  }
  ```

### 2. 删除数据 API (小辈剔除隐私/无关内容)
前端小辈在列表页进行筛选，对于不想让长辈看到的素材，调用此接口进行批量删除（或标记为隐藏）。

* **接口路径:** `POST /api/v1/data/raw/delete`
* **功能描述:** 批量删除不需要交给 Agent 处理的原始数据。*(注：在 RESTful 规范中，带 Request Body 的批量删除通常采用 POST 方法更稳妥)*
* **Body 参数:**
  ```json
  {
    "item_ids": ["raw_001", "raw_003"], // 需要删除的原始数据 ID 列表
    "user_id": "user_123"
  }
  ```
* **响应示例 (Response):**
  ```json
  {
    "code": 200,
    "message": "成功删除 2 条数据",
    "data": {
      "deleted_count": 2
    }
  }
  ```

### 3. 获取 Agent 结果数据 API (触发翻译与摘要生成)
小辈完成初筛后点击“生成”，前端调用此接口，后端组装当日**剩余的**原始数据，喂给大模型进行处理，并返回“家书”结果。

* **接口路径:** `POST /api/v1/agent/generate-summary`
* **功能描述:** 触发 Agent 对当日数据进行“长辈友好型”翻译，并返回结构化数据供小辈进行最终审核。
* **Body 参数:**
  ```json
  {
    "date": "2023-11-24",
    "user_id": "user_123"
  }
  ```
* **响应示例 (Response):**
  ```json
  {
    "code": 200,
    "message": "Agent 处理完成",
    "data": {
      "summary_id": "sum_998",
      "title": "小明今天吃了一顿丰盛的晚餐",
      "content": "爸妈，我今天工作挺努力的，晚上下班后去吃了一顿火锅犒劳自己，现在感觉好多了，你们放心吧！",
      "cover_image": ["https://example.com/images/hotpot.jpg","https://example.com/images/hotpot.jpg"],
      "suggested_questions": [ // 生成给长辈的预设问题按钮
        "看着真香，这是和谁一起吃的呀？",
        "最近降温了，吃饭穿够衣服没？"
      ]
    }
  }
  ```
*(注：如果大模型处理较慢，黑客松演示时可在前端做一个 2-3 秒的“Agent 思考中…”的 Lottie 动画来掩盖接口耗时。)*

### 4. Agent 对话 API (长辈互动与陪聊)
部署在长辈“电子相框”端的接口。当长辈点击生成的提问按钮，或语音输入时调用，Agent 基于当前相片和历史记忆做出回答。

* **接口路径:** `POST /api/v1/agent/chat`
* **功能描述:** 接收长辈的提问，结合当前展示的动态和 Mem0 记忆，返回 Agent 的贴心回答，或生成给小辈的关怀留言。
* **Body 参数:**
  ```json
  {
    "query": "看着真香，这是和谁一起吃的呀？", // 长辈的问题
    "summary_id": "sum_998"// 传递当前的上下文 ID，让 Agent 知道长辈在看哪张图
  }
  ```
* **响应示例 (Response):**
  ```json
  {
    "code": 200,
    "message": "success",
    "data": {
      "reply_text": "奶奶您好！我看照片里对面坐着两个同事，小明应该是和他们一起聚餐呢。小明最近心情不错，您别担心。",
      "action": "reply" // 枚举值：reply (直接回答), notify_younger (触发了需要发给小辈的关怀通知)
    }
  }
  ```
